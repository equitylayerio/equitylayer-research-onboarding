# Local client verification boundary

The local client is an unpublished development candidate, not an accepted production release.
Installing source code does not supply an AI account, source dataset, research subscription, or commercial data rights.
Use [first-use setup](first-use.md) with your existing AI. Use [installation and recovery](installable-client.md) for private storage.

## What the checks establish

| Evidence | Boundary |
| --- | --- |
| Synthetic storage and controller tests | Transactions, references, leases, request reservations, separate review actions, and retained history. |
| Offline installed-client checks | Package entry resolution, local MCP framing, task preparation, synthetic return, copy-upgrade, and recovery. |
| Isolated desktop/mobile checks | Selected Inbox, Tracking, source-selection, and failure-display interactions with synthetic workspaces. |
| Temporary macOS worker checks | Bounded restart and stop behavior with synthetic sources, not a user's installed monitoring service. |

The local.22 baseline passed 1501 automated tests on macOS with Node 24.22.1.
Those counts describe that baseline, not a future archive, GitHub CI run, or all supported operating systems.
Run `npm test` from the reviewed source candidate for its current automated result.
Node 22 SQLite support is experimental. New-platform and unaided-user checks remain separate requirements.

## Research and readable sources

Supported retained UTF-8 artifacts can supply pinned original bytes and readable source ranges.
Hashes detect differences from the retained version. They do not establish source authenticity, complete disclosure, or commercial permission.
Publication dates, observation times, reporting periods, and research cutoffs remain distinct.
Missing, unsupported, held, or stale evidence must remain explicit.

One bounded Codex financial trial returned research from retained TTM and EMC documents and survived reopening.
It used installed local.19 modules with an additional private submission-limit launcher.
That launcher restricted calls without changing forwarded values or the product validator.
This result is not a trial of the unmodified default installed entrance, a current market report, or approved research.
Founder review, a second real update, and an unaided user's successful return remain incomplete.
No synthetic run or interface check replaces those requirements.

A separate October 26 trial used an unchanged local.23 installed MCP server, without the private submission launcher.
It returned one initial research record in about 104 seconds, with no retry, timeout, or source fetch.
The record survived reopening. Independent QC checked authenticated local HTTP reads and selected financial anchors.
That trial used engineering-prepared retained sources and bounded caller instructions. It was not unaided onboarding or complete research acceptance.
The result remains unreviewed. Source rights, complete currentness, a second update, and user pilots remain separate gates.

## Source checks and workers

The fixed TWSE adapter and SEC submissions-index detector have deterministic parser, policy, scheduling, and failure tests.
An SEC index is filing metadata, not the corresponding financial statement.
TWSE issuer revenue does not establish AI-only or material-grade revenue, margins, qualification, or customer relationships.
No local permission declaration verifies commercial rights or permits redistribution.

Configuration, a heartbeat, a successful source check, returned research, and accepted evidence are different states.
Opening a notice and preparing a connection do not invoke AI.
Observation-only recovery does not start a worker or restore source permission.
Unknown model usage retains its accounting gate and reservation.
